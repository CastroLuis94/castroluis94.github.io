Cómo construir un Agente de Reservas Híbrido: Combinando LLMs Locales con Lógica Determinista

Una guía paso a paso sobre cómo resolver problemas de intents, cortocircuitos lógicos de FAQs y validación robusta de datos usando FastAPI y Ollama.

Luis Castro Machine Learning Lead & Engineer

Introducción

Integrar Modelos de Lenguaje (LLMs) para interfaces de chat conversacionales es una solución potente, pero confiar el 100% del flujo de negocio a un modelo generativo puede traer problemas de inconsistencia. Los modelos más pequeños de parámetros optimizados para consumo local a veces fallan al interpretar estructuras muy simples o se confunden cuando un usuario responde con un solo dato aislado.

En este artículo, analizamos cómo estructurar un backend en FastAPI que actúa como un framework híbrido, utilizando un LLM para la extracción inicial y aplicando capas de lógica determinista para garantizar una experiencia de usuario robusta y sin fallos.

El Desafío: El Cortocircuito de Intenciones (FAQ vs. Reserva)

Uno de los primeros obstáculos lógicos surge cuando el usuario interrumpe un flujo activo (como el llenado de datos de una reserva) para hacer una consulta informativa de tipo FAQ, por ejemplo: "¿Qué días abre?".

Fallo común: Si el estado de la sesión marca que hay una reserva en proceso, el enrutador tiende a ignorar la intención informativa, cayendo en un bucle que insiste en pedir los datos faltantes o devolviendo una respuesta genérica como "¿En qué puedo ayudarle?".

La solución aplicada fue establecer un orden de prioridades en el router de FastAPI, interceptando las intenciones de tipo horario de manera inmediata, respondiendo la consulta y manteniendo el estado de la sesión intacto para no perder el progreso del usuario.

Lógica Determinista al Rescate: Extracción de Entidades Cortas

Los modelos de lenguaje compactos suelen clasificar como "general" las respuestas que contienen únicamente un nombre propio (ej: "Luis Castro") al no encontrar verbos ni contexto de reserva. Al no detectar la entidad, el sistema vuelve a preguntar intermitentemente el mismo campo.

Para solucionar esto de raíz, implementamos una validación cruzada: si el sistema requiere activamente un campo como el Nombre y el mensaje del usuario no contiene indicadores de fechas o números, se fuerza un análisis mediante expresiones regulares avanzadas que aíslan e insertan la cadena de texto directamente en el estado.

Flujo de Conversación Exitoso

Una vez unificadas las capas deterministas con las heurísticas del LLM local, el agente maneja las consultas informativas sobre la marcha, recupera el hilo conductor de la reserva sin perder contexto, extrae las entidades correctamente paso por paso y solicita la confirmación final explícita antes de impactar el backend.

Persistencia de Datos en Airtable

El paso final del ciclo es el almacenamiento. Al procesar la respuesta afirmativa, los datos limpios y normalizados estructuran un nuevo registro tanto en la tabla relacional de clientes como en el control de reservaciones.

Conclusión

Combinar la flexibilidad conversacional de los LLMs con la confiabilidad de las reglas de negocio cableadas en código (RegEx y estructuras condicionales en Python) ofrece lo mejor de ambos mundos: una IA amigable que no rompe la base de datos ni frustra al usuario. El agente ahora es capaz de guiar al cliente fluidamente hasta registrar con éxito la reserva.
